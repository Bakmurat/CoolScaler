# Security posture

## Two gates before anything is mutated

- `readOnly=true` (default). Every apply path in the recommender, updater and
  webhook checks it. The API reports `readOnly` so the UI disables actions.
- `WRITE_ENABLED` is derived by the chart as `not readOnly`. It gates the lower
  level: writing Recommendation and seed custom resources, ConfigMaps, the webhook
  TLS Secret, CRD updates, and leader-election Leases. With it off, components
  log the request they would have made (dry-run) instead of sending it.

Set `readOnly=false` only after you have read the recommendations for a while and
agree with them.

## Admission webhook

- Mutates only pods in namespaces labeled `coolscaler.sh/optimize=true`, never
  `kube-system` or the release namespace.
- Also sees HPA and KEDA ScaledObject updates to mark them as managed.
- `failurePolicy: Ignore` (fail-open): if the webhook is down, pods are created
  unchanged. This is deliberate so CoolScaler can never block scheduling; the
  trade-off is that a failed webhook silently stops injecting. Change it to
  `Fail` in `charts/coolscaler/templates/admissions.yaml` if you prefer blocking.
- Serving certificates are generated by Helm and stored in a Secret; the binary
  can also generate its own (`--gen-cert`) when the Secret is absent.

## RBAC scope

The ClusterRole (`charts/coolscaler/templates/rbac.yaml`) lists what the code
uses:

- Read: pods, nodes (and `nodes/metrics`, `nodes/proxy`), namespaces, services,
  endpoints, PVCs, PVs, events, quotas, limit ranges, Deployments, StatefulSets,
  DaemonSets, ReplicaSets, Jobs, CronJobs, PodDisruptionBudgets, PriorityClasses,
  HPAs, KEDA ScaledObjects, Ingresses, Istio VirtualServices and Gateways,
  `metrics.k8s.io`, its own ClusterRole, and the `/metrics` endpoints.
- Own state: all verbs on `analysis.coolscaler.sh` resources; ConfigMaps
  (create/update/patch/delete), Secrets (get/create/update/patch), Leases,
  CustomResourceDefinitions (create/update/patch), MutatingWebhookConfigurations
  (update/patch), Events (create).
- Apply (inert while read-only): patch/update Deployments, StatefulSets, DaemonSets
  (plus create/delete for headroom pause Deployments), `pods/resize`, pod
  eviction and deletion (observability healing), namespace label patches, HPAs,
  ScaledObjects, Ingresses and VirtualServices (Settings > Ingresses).

The role is cluster-scoped, so verbs on ConfigMaps and Secrets apply cluster-wide
even though CoolScaler only touches its own namespace. `rbac.unrestricted=true`
adds a wildcard rule for clusters where a feature hits a gap; it is off by
default and should stay off in shared clusters.

## What to review before production use

- Run in read-only mode first and compare recommendations against your own
  judgement; check the cost model matches your prices.
- Decide on the webhook failure policy.
- Restrict the dashboard: it has no authentication of its own. Put it behind your
  ingress auth or keep it on a port-forward.
- The Slack integration stores a bot token in a ConfigMap edited from the UI;
  treat the release namespace accordingly.
